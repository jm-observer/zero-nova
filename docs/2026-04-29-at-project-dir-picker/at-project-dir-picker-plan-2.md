# Plan 2: 前端 @ 弹层交互与路径插入

## Plan 编号与标题
Plan 2: 前端 @ 弹层交互与路径插入

## 前置依赖
- Plan 1: Tauri 目录枚举命令与安全边界

## 本次目标
- 在聊天输入框支持 `@` 触发目录选择。
- 支持目录下钻、回退与文件选择插入。
- 支持弹层展示后基于用户继续输入做实时过滤。
- 提供键盘与鼠标双通道操作。

## 涉及文件
- `deskapp/src/ui/chat-view.ts`（输入监听、弹层状态机、选择行为）
- `deskapp/src/styles/main/chat.css`（弹层样式）
- （可选）`deskapp/index.html`（若需要新增容器节点）

## 详细设计
### 1. 触发与关闭规则
触发条件：
- 输入框中光标附近出现 `@` token，且 token 尚未被空白截断。
- 首次触发时加载 project dir 根目录。

关闭条件：
- 按 `Esc`。
- 光标离开 `@` token 语境。
- 选择文件后插入完成。
- 输入框失焦且未点击弹层。

### 2. 状态模型
建议在 `ChatView` 内维护最小状态：
- `visible`: 是否显示弹层
- `loading`: 是否正在拉取目录项
- `baseTokenStart`: 当前 `@` token 起始位置
- `currentRelativePath`: 当前浏览目录（空字符串表示根目录）
- `entries`: 当前目录全部项
- `filteredEntries`: 根据当前关键字过滤后的可见项
- `filterKeyword`: `@` 后当前输入关键字（不含目录前缀）
- `activeIndex`: 键盘高亮索引
- `breadcrumb`: 路径层级（用于展示当前位置）

### 3. 目录下钻与文件插入
- 点击目录：更新 `currentRelativePath` 并请求下一层。
- 点击文件：将 `@<relativePath>` 替换当前 token，末尾补空格，便于继续输入。
- 提供“返回上级”伪条目（`..`）或 breadcrumb 点击回退。

### 4. 实时过滤规则
- 用户在 `@` token 后继续输入时，解析当前 token 的最后一段作为 `filterKeyword`，对 `entries` 做前端过滤。
- 过滤匹配建议使用不区分大小写的 `includes`（匹配 `name`，可选匹配 `relativePath`）。
- 过滤后列表为空时显示“无匹配项”空状态，不自动关闭弹层。
- 当用户下钻目录后，过滤仅作用于当前目录上下文，不跨目录检索。
- 输入回删时应立即恢复匹配项；清空关键字后恢复当前目录完整列表。

### 5. 键盘交互
- `ArrowDown/ArrowUp`：移动高亮。
- `Enter`：选择高亮项（目录下钻或文件插入）。
- `Tab`：与 Enter 同步行为（可选）。
- `Esc`：关闭弹层。

### 6. UI 样式
弹层放置建议：
- 锚定在输入区容器内，位于 textarea 上方，避免被消息列表遮挡。
- 最大高度 + 滚动。
- 当前目录路径头部 + 条目列表主体。
- 目录与文件图标区分，激活项高亮清晰。
- 当过滤生效时在头部显示轻量提示（如“筛选: xxx”），便于用户理解当前视图。

### 7. 性能与可用性
- 对输入事件做轻量节流（仅在 token 变化时请求）。
- 请求并发时保留最后一次请求结果，避免乱序覆盖。
- 目录条目数量大时，先渲染可视区域（或限制单次展示数量）。
- 过滤优先在前端本地执行，避免每个键入都触发后端 I/O。

## 测试案例
### 正常路径
1. 输入 `@` 后展示根目录。
2. 选择目录后显示子目录内容。
3. 弹层出现后继续输入关键字，列表实时过滤。
4. 选择文件后输入框插入 `@相对路径` 并关闭弹层。

### 边界条件
1. 目录为空时显示空状态。
2. 路径层级较深时 breadcrumb 可回退。
3. 连续输入多个 `@` token 时仅作用于当前光标 token。
4. 关键字大小写不同但应匹配同一条目。
5. 回删关键字后列表正确恢复。

### 异常路径
1. 后端返回错误时展示非阻塞错误提示，弹层保留可重试。
2. 请求超时或网络抖动时不影响普通消息发送。
3. IME 组合输入期间不误触发确认行为。
