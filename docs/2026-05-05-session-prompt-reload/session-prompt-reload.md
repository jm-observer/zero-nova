## 项目现状

1. 当前 Session 的 system prompt 由多段来源拼接生成，不是单一字符串字段。
2. 前端缺少针对“重读配置并重拼接 system prompt”的显式操作入口。
3. 运行中的 Session 在启动后持有内存态 prompt，配置变更不会自动反映到现有 Session。
4. 若直接提供“在线编辑最终 system prompt”能力，会绕开既有配置与拼接规则，增加语义分叉和维护风险。

## 整体目标

1. 保持“配置为 source of truth”，用户通过修改配置提示词来源来生效，不直接覆盖最终拼接结果。
2. 前端新增“重新加载/更新”操作，触发当前 Session 执行“重读配置 + 重拼接 + 原子替换”。
3. 明确并发语义：重载只影响后续请求，不影响已经开始执行的请求。
4. 明确失败语义：重载失败时保留旧 prompt，不写入半成品状态。
5. 提供最小可观测性：记录重载操作结果与版本指纹，不记录完整 prompt 内容。

## 风险与待定项

### 已知风险

1. 配置文件热更新与手动重载可能同时发生，若无版本比较可能出现“旧值覆盖新值”。
2. 重载时若直接持锁执行耗时 IO，可能阻塞会话请求路径。
3. 若日志输出完整 prompt，可能泄露敏感信息。

### 待确认项

1. “重新加载”是否仅针对当前 Session，还是支持批量对同项目全部 Session 生效。
2. 配置读取路径是否固定，是否允许多环境/多 profile。
3. 前端是否需要“恢复默认提示词”快捷入口（本次默认不做）。

## 建议实施顺序

1. 先收敛数据结构和版本策略，避免后续接口字段反复调整。
2. 再实现后端重载链路与并发控制，确保语义正确。
3. 最后接前端按钮与提示，完成端到端验证与回归测试。
