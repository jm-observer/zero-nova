## 本次目标
建立覆盖后端采集、持久化、前端渲染与交互的测试矩阵，确保功能稳定并避免对现有聊天流程产生回归。

## 涉及文件
- `crates/nova-agent/tests/integration/*`（新增或扩展）
- `deskapp/src/__tests__/*`（消息渲染与交互测试）
- 必要的 schema fixture（如项目已有 fixture 目录）

## 详细设计
1. 后端测试：
- Provider 请求/响应采集单测（含流式聚合）。
- 消息落库存储与反序列化测试（验证 metadata 结构与 `boundMessageId`）。

2. 前端测试：
- assistant 消息按钮渲染快照/DOM 断言。
- 点击复制后剪贴板调用参数断言（pretty JSON）。
- 无数据/数据异常/复制失败分支断言。

3. 集成测试：
- 发送一次消息，等待 assistant 完成，拉取消息列表，断言可见并可复制两类 body。
- 刷新/重连后再次拉取，断言历史可回看。

4. 回归范围：
- 现有消息发送、流式 token、工具调用展示、会话切换不受影响。

## 测试案例
1. 正常：完整 trace + 双按钮可复制。
2. 边界：大 body 截断标记仍可复制可解析 JSON。
3. 异常：Provider 错误场景不写入脏 trace，前端安全降级。
4. 持久化：重启服务后历史消息 trace 仍存在。
5. 性能：批量历史消息渲染无明显卡顿（可用基准阈值或 smoke 指标）。
