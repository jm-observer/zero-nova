# Plan 3: 前端交互与状态反馈

## 前置依赖
Plan 1, Plan 2

## 本次目标

在前端提供可见、可控的“重新加载/更新系统提示词”操作，并清晰反馈执行状态与当前生效版本，降低误操作和不确定性。

## 涉及文件

- `deskapp/src/pages/session/*`（会话页面或设置面板）
- `deskapp/src/core/gateway-client.ts`
- `deskapp/src/core/types.ts`
- `deskapp/src/store/*`（会话状态管理）
- `deskapp/src/**/__tests__/*`（前端交互测试）

## 详细设计

### 1. 交互入口

在 Session 设置区增加按钮：

- 主按钮文案：`重新加载系统提示词`
- 次级展示：当前版本（短哈希）与最后更新时间

### 2. 调用链路

1. 点击按钮后调用 `session.system_prompt.reload`。
2. 按钮进入 loading，防止重复点击。
3. 成功后刷新本地 Session 元信息：
   - `systemPromptVersion`
   - `systemPromptUpdatedAt`

### 3. 反馈文案

1. 成功且 `changed = true`：提示“已更新，后续请求将使用新系统提示词”。
2. 成功且 `changed = false`：提示“配置已重新加载，内容未变化”。
3. 失败：提示“重载失败，当前会话仍使用旧系统提示词”并展示简短错误原因。

### 4. 状态一致性

1. 前端不缓存完整 prompt 文本，只缓存版本与时间。
2. 若会话切换，按钮状态与版本展示需随 Session 维度隔离。
3. 重载完成后不自动重发当前正在输入的用户消息，避免意外重复请求。

### 5. 可用性细节

1. 操作期间禁用按钮并显示旋转图标。
2. 错误提示支持“复制错误详情”以便排查。
3. 版本展示采用前 8 位哈希，完整值可 hover 查看。

## 测试案例

1. 点击按钮成功后，显示成功提示并更新版本时间。
2. 返回 `changed = false` 时显示“内容未变化”提示。
3. 接口失败时展示错误提示，按钮从 loading 恢复。
4. 快速连点按钮只发送一次请求（去重生效）。
5. 切换 Session 后展示对应版本，不串数据。
