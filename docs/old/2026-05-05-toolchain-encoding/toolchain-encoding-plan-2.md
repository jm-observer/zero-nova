# Plan 2: 工具调用参数规范化

## 前置依赖
Plan 1

## 本次目标
建立严格的工具参数校验与标准化流程，禁止 schema 外字段进入执行器，减少异常路径和隐式行为。

## 涉及文件
- `crates/*/src/*tool_schema*.rs` — 工具参数定义
- `crates/*/src/*tool_dispatch*.rs` — 工具调用分发与参数解析
- `crates/*/src/*validation*.rs` — 参数校验逻辑

## 详细设计

### 1. 参数解析策略

从“宽松反序列化”改为“严格反序列化”：
- 对每个工具入参结构开启未知字段拒绝策略（如 `deny_unknown_fields`）。
- 遇到未知字段直接返回可读错误：指出字段名、工具名、合法字段列表。

### 2. 调用层标准化

在进入业务执行前，统一进行参数标准化：
1. 必填字段完整性检查。
2. 字段类型校验（避免字符串数字混用等隐式转换）。
3. 平台相关字段合法性检查（例如 shell 类型与命令格式匹配）。

### 3. 错误分级

参数问题统一归类为 `InvalidToolArguments`，与执行失败区分：
- 参数错误：不启动子进程。
- 执行错误：参数通过后启动子进程但命令失败。

### 4. 兼容与迁移

对历史调用中常见的违规字段（如 `description` 混入 `arguments`）给出明确迁移提示：
- 提示“该字段不在 schema 中，已拒绝执行”。
- 附带示例正确参数结构。

## 测试案例

1. **合法参数**：正常通过并执行。
2. **包含未知字段**：直接返回 `InvalidToolArguments`，不启动进程。
3. **缺失必填字段**：返回明确缺失项。
4. **类型不匹配**：返回字段级错误信息。
5. **回归测试**：覆盖历史问题样例（`arguments` 混入 `description`）。
