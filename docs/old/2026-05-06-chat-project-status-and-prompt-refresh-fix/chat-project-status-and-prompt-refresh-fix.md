## 项目现状

1. 聊天输入框上方 `Project` 菜单的显示值来自前端缓存 `sessionProjectDirState` 与 runtime 读取混合路径，更新时机分散在 `SESSION_SELECTED`、`session.runtime.updated`、手动刷新三条链路中，存在状态不同步窗口。
2. `Project` 菜单“刷新”当前仅拉取一次 `session.runtime`，但未建立“刷新后状态版本校验 + UI 明确反馈”，用户无法判断拿到的是旧值还是新值。
3. 标题栏连接状态由 `Events.GATEWAY_STATUS` 承载，既承载 `connectionStatus`（连接态）又承载 `status/text`（运行态文案），存在语义复用；聊天流过程还会主动发 `status: running`，容易覆盖连接态感知。
4. Prompt 面板“重新加载”调用 `session.system_prompt.reload` 后会触发 `loadPromptMemoryData`，但“重载结果版本”和“当前展示版本”的一致性校验与可视提示不足，用户感知为“点击重载但展示仍不是最新”。

## 整体目标

1. 修复聊天区 `Project` 菜单在项目路径切换后的滞后显示问题，保证“状态源单一、刷新可验证、界面可感知”。
2. 收敛标题栏状态模型，确保连接状态不会被运行文案误覆盖，杜绝“始终连接中”的假象。
3. 为 Prompt 重载建立“请求结果 -> runtime/version 对齐 -> 展示确认”的闭环，保证前端看到的是重载后的最新版本。
4. 增加端到端回归测试与诊断日志，覆盖正常路径、竞态路径、失败路径。

## 关键问题归纳

### 问题 A：聊天区 Project 显示不是最新

现象：切换项目路径后，聊天框上方 `Project` 文案不更新；点击刷新后仍旧值。

初步根因：

1. `ChatView` 同时使用 `sessionProjectDirState` 本地缓存和 `state.sessionRuntimeStates`，二者更新顺序可能错位。
2. `refreshProjectMenuState()` 拉取 runtime 后仅做赋值与重绘，没有“是否为新版本”的判断与提示。
3. 运行态更新事件若延迟到达，可能被更早的本地状态覆盖，出现回退。

### 问题 B：标题栏一直显示连接中

现象：实际已经可聊天/可请求，标题栏仍“连接中”。

初步根因：

1. `gateway:status` 事件复用两种语义：连接态（`connectionStatus`）和业务运行文案（`status/text`）。
2. 聊天流程中会频繁发送 `status: running`，与连接态展示路径共享入口，存在覆盖或误判风险。
3. 标题栏未对“连接态优先级”和“运行文案展示域”做严格隔离。

### 问题 C：Prompt 重新加载后展示不是最新

现象：点击“重新加载提示词”后，界面没有明确反映最新内容。

初步根因：

1. 重载动作成功后虽触发重新拉取，但缺少“重载返回版本 vs 当前展示版本”的一致性断言。
2. 若拉取发生在配置落地或 runtime 广播之前，可能读到旧快照，且无二次补偿刷新。
3. 面板缺少“已对齐到 version=xxx”类确认信息，用户只能凭肉眼判断。

## 风险与待定项

### 已知风险

1. 若仅改 UI 渲染不改事件语义，后续新功能仍会复用旧事件导致回归。
2. 若刷新动作增加重试但无节流，可能造成重复请求与闪烁。
3. Prompt 版本字段若后端为空，前端一致性判断会退化，需要降级策略。

### 待确认项

1. 标题栏是否需要同时展示“连接态 + 运行态”双标签；本次默认优先保证连接态准确。
2. Project 菜单刷新失败是否需要 toast 明示；本次建议增加明确失败提示。
3. Prompt 面板是否展示“上次重载时间”；本次可作为增强项。

## 建议实施顺序

1. 先收敛事件与状态模型（Plan 1），避免边改边漂移。
2. 再修 Project 与标题栏（Plan 2、Plan 3），消除主要可见问题。
3. 最后修 Prompt 重载闭环与测试（Plan 4），形成完整回归保护。
