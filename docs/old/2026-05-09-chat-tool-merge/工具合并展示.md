### 当前行为

2. **工具结果返回**（`tool_result` 事件）：
   - 由 `handleToolResult()` 处理（chat-view.ts:1301-1343）
   - 创建 `<div class="tool-result-card" data-rel-id="xxx">` 兄弟元素
   - 包含结果头部和内容
   - 设置 15 秒自动折叠计时器

3. **工具日志**（`tool:log` 事件）：
   - 由 `handleToolLog()` 处理（chat-view.ts:1232-1258）
   - 通过 `data-tool-use-id` 直接定位到 `tool-use-card` 内部

4. **ID 匹配机制**：
   - `tool-use-card` 使用 `data-tool-use-id` 属性
   - `tool-result-card` 使用 `data-rel-id` 属性
   - 两者共享同一个 `toolUseId` 值

### 主要差距（Gap）

| 方面 | 当前行为 | 目标行为 |
|------|----------|----------|
| DOM 结构 | 兄弟元素并列 | 结果卡嵌套在调用卡内部 |
| 折叠联动 | 各自独立折叠 | 展开调用卡时自动展开结果卡 |
| 视觉层级 | 平铺展示 | 嵌套层级展示 |
| 结果卡定位 | 插入到 markdown-body 末尾 | 插入到对应 tool-use-card 内部 |

## 整体目标

将前端聊天窗口中的工具调用（Tool Call）与工具结果（Tool Result）从**并列兄弟元素**改为**嵌套关系**，实现：

1. 工具结果卡插入到对应的工具调用卡内部
2. 折叠/展开行为联动
3. 保持现有事件处理逻辑的最小改动
4. 保持 `tool_log` 事件兼容性（日志仍显示在调用卡内部）

## 风险与待定项

1. **消息恢复场景**：`MESSAGES_UPDATED` 事件会重新渲染所有消息，需要确认 `renderMessages` 中的 `buildToolHtml` 函数是否正确处理嵌套结构
2. **流式消息边界**：工具调用/结果可能在流式消息（streaming message）中，也可能在独立消息中，需确保两种场景都正确处理
3. **动画过渡**：嵌套结构改变后，CSS 过渡动画可能需要调整
4. **toolUseId 唯一性**（开放问题）：需确认 `toolUseId` 是全局唯一还是会话内唯一，这决定缓存键和 orphan 处理策略
5. **历史消息 orphan 处理**（开放问题）：历史消息恢复时，是否允许"孤立 tool_result"继续独立展示，还是要统一归并到最近一次 tool_use
