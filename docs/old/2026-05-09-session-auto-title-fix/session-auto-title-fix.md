# Session Auto Title Fix

## 时间
- 创建日期：2026-05-09
- 最后更新：2026-05-09
- 更新说明：基于代码 review 输出修复方案，覆盖状态持久化、推送链路、生成器与失败状态机

## 项目现状
- 已实现基础自动标题触发与标题归一化，但存在关键一致性缺陷：
  - `TitleState` 实际读写在 `Session.title_state`，与 `ControlState.title_state` 分离，导致重启后状态丢失。
  - 前端已监听 `session.summary.updated`，但后端没有稳定发射该事件。
  - 标题生成逻辑目前为用户文本拼接，不是独立生成器调用。
  - 失败路径状态机在异步任务异常时可能停留在 `Pending`。

## 整体目标
- 修复会话标题自动生成在“持久化、幂等、推送同步、失败恢复、可测试性”上的行为缺口。
- 确保以下结果可验证：
  - 标题状态重启不丢失，成功后不会重复生成。
  - 标题变更可通过 `session.summary.updated` 实时推送到前端。
  - 生成器具备明确接口，可替换为真实 LLM 实现，失败不阻塞聊天主流程。
  - 失败状态机不会卡死在 `Pending`。

## 风险与待定项
- 风险：若在 `ConversationService` 内直接耦合具体 LLM provider，后续迁移成本高；需先引入窄接口。
- 风险：会话标题推送若在多处重复触发，可能产生前端抖动；需定义统一发射点和幂等条件。
- 风险：历史数据中 `runtime_control` 可能缺失 `title_state` 字段；需保持默认反序列化兼容。
- 待定：标题生成超时是否计入 `attempt_count`，建议纳入配置并在 Plan 3 固化策略。
